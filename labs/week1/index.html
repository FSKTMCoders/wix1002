1 · Before you begin

By the end of this lab, you should be able to run and modify Java code, record changes with Git, push a practice project to GitHub, and begin applying for GitHub Education benefits.

You need a Windows, macOS, or Linux computer, internet access, permission to install software, and access to your email. For the Education application, prepare your university email and proof of current enrolment.

Path A · Apache NetBeans

A complete integrated development environment (IDE) with Java project management, an editor, and Run/Debug tools. Codelerity provides NetBeans packages bundled with a JDK runtime.

Choose NetBeans →

Path B · Visual Studio Code

An editor with Java support provided by a JDK and extensions. Microsoft’s Coding Pack combines these components on Windows and macOS.

Choose VS Code →
Complete one IDE path, then continue from Section 4. You do not need both IDEs. The Java Development Kit (JDK) contains the compiler and development tools; an editor alone cannot compile Java. Use the course JDK version if your lecturer specifies one. Otherwise use the supported JDK supplied or recommended by your chosen installer, and record its version.

2 · Path A: Apache NetBeans

A1 · Download and install

  1. Open Codelerity’s Apache NetBeans page.
  2. Choose the current package for your operating system and processor. On macOS, check Apple menu → About This Mac for Apple silicon or Intel. On Windows, check Settings → System → About. Select the corresponding ARM64 or x64 package where offered.
  3. Read the package’s operating-system and JDK requirements. Prefer the bundled-JDK package for a straightforward setup; a separate Java installation is normally unnecessary just to launch that package.
  4. Windows: run the installer and follow its prompts. macOS: open the downloaded installer or disk image and follow its instructions. Linux: follow the page’s instructions for the offered package format. Keep default options unless you have a reason to change them.
  5. Launch Apache NetBeans from your applications menu. Allow first-run configuration to finish.

A2 · Check Java and create your project

  1. Open Tools → Java Platforms. Confirm that a Java SE platform is listed. Record its JDK version and location. The JDK used to run the IDE and the one selected for your project can differ.
  2. Choose File → New Project → Java with Maven → Java Application, then Next. Stay connected: Maven may need to download components.
  3. Name the project WIX1002Week1 and place it in a course folder under Documents. If prompted, use group ID edu.um.wix1002, artifact ID wix1002-week1, and package edu.um.wix1002. Click Finish.
  4. Under Source Packages, right-click the edu.um.wix1002 package and choose New → Java Class. Name the class HelloJava. Enter the package name in the dialog if it was not created automatically.
  5. Open HelloJava.java. Keep the generated package edu.um.wix1002; line, then replace the class underneath it with the program in Section 4.
  6. Save, right-click HelloJava.java, and choose Run File. Read the Output pane. If you run the entire project instead, select edu.um.wix1002.HelloJava as the main class when asked.
Checkpoint: the Output pane displays Welcome to WIX1002!. A bundled JDK can work inside NetBeans even when a separate terminal cannot find java; configuring the system PATH is a separate task.

If Java project categories are missing, check Tools → Plugins and activate your installation’s Java support. If Maven downloads fail, check the network and retry. Ask your tutor if the required project JDK is missing.

Continue to Section 4 →

3 · Path B: VS Code for Java

B1 · Install Java support

  1. Open Microsoft’s Getting Started with Java in VS Code guide.
  2. Windows/macOS, starting fresh: choose the guide’s Coding Pack for Java installer for your OS. Follow its prompts to install VS Code, a JDK, and Java extensions.
  3. Linux, or an existing VS Code installation: install VS Code if needed, and a supported JDK from a provider listed in the guide, such as Eclipse Temurin. Choose a JDK, rather than a JRE, with the correct OS and processor architecture. Follow the provider’s installer or package-manager instructions.
  4. Open VS Code’s Extensions view. Install Extension Pack for Java by Microsoft, or verify it is enabled if the Coding Pack installed it already. You do not need the generic Code Runner extension for this lab.
  5. Reopen VS Code, choose Terminal → New Terminal, and run:
java --version
javac --version

Both commands should print versions. If either is missing, follow your JDK installer’s PATH instructions. When setting JAVA_HOME, use the JDK root folder, and add its bin folder to PATH. Reopen the terminal after changing these settings.

B2 · Create and run a project

  1. Open the Command Palette: Ctrl+Shift+P on Windows/Linux or Cmd+Shift+P on macOS. Run Java: Configure Java Runtime to inspect detected JDKs. Select the course JDK for your project if required.
  2. Run Java: Create Java Project, choose No build tools, select your course folder, and name the project WIX1002Week1.
  3. Open the project folder. Create HelloJava.java inside src. This exercise uses the default package, so no package line is needed.
  4. Paste the program in Section 4, save, and wait for Java language support to finish loading.
  5. Click Run above the main method. Read the greeting in the terminal or output view selected by the Java extension.
Checkpoint: the program displays Welcome to WIX1002!. If Run is missing, open the whole project folder, check the .java extension and Java extensions, and allow Java support to finish loading.

4 · Run, modify, and explain

public class HelloJava {
    public static void main(String[] args) {
        System.out.println("Welcome to WIX1002!");
        System.out.println("My name is YOUR NAME.");
    }
}

The public class and filename must match: HelloJava and HelloJava.java, including capitalisation. NetBeans users should retain the generated package declaration above this code; the VS Code path here uses no package declaration.

  1. Replace YOUR NAME with your name and run the program.
  2. Add a third output statement that prints I am ready to learn Java. Save and run again.
  3. Explain where execution starts, what println does, and why the filename matters.
  4. Temporarily remove a semicolon from one statement. Read the compiler error, restore the semicolon, and run again.
Expected output after adding the third line
Welcome to WIX1002!
My name is YOUR NAME.
I am ready to learn Java.

The second line should contain your actual name.

5 · What is Git? Install and configure it

TermMeaningIn this lab
GitA local version-control tool that records file history. It works without GitHub.Record versions of your Java code.
GitHubAn online service that hosts Git repositories and supports collaboration.Store a remote copy of your practice project.
RepositoryA project’s files and Git history.Your project folder after initialising Git.
CommitA recorded snapshot with a message explaining the change.“Add first Java lab program”.
PushSend local commits to a remote repository.Upload your history to GitHub.
CloneCopy an existing repository and its history into a new local folder.Start working on an existing project.
Workflow: edit → stage selected changes → commit locally → push to GitHub. Saving in an IDE is not a commit; a commit is not automatically uploaded.

Install Git and set your identity

  1. Open Git’s official downloads page and follow the instructions for your OS. On Windows, select the option that makes Git available from the command line. On macOS, the page lists installation options including Apple’s command-line tools. On Linux, use its package-manager instructions.
  2. Open a new terminal: Git Bash or PowerShell on Windows, Terminal on macOS/Linux, or your IDE terminal. Run git --version.
  3. Set your name and email, replacing the examples below. Use an email verified on your GitHub account so GitHub can associate your commits with you.
git --version
git config --global user.name "Your Name"
git config --global user.email "your-verified-email@example.com"
git config --global --get user.name
git config --global --get user.email

To keep an email private in commits, copy your exact GitHub noreply address from Settings → Emails and use that address. On a shared computer, omit --global and set identity inside your repository after initialising it.

Make your first local commit

  1. Open a terminal in the project root: the folder containing pom.xml in the NetBeans Maven project, or src in the VS Code project. Do not initialise Git in your whole Documents folder.
  2. Create .gitignore at the project root with:
*.class
target/
build/
dist/
bin/
nbproject/private/
.vscode/
.DS_Store
Thumbs.db
  1. Create README.md in the project root. Record your IDE choice, JDK version, and how to run HelloJava.
  2. Run git init, then stage your files. Both IDE paths in this lab put Java source under src.
git init
git add .gitignore README.md src

NetBeans Maven users: also run git add pom.xml now to include the build configuration. Then everyone runs:

git status
git commit -m "Add first Java lab program"
git branch -M main
git log --oneline
Checkpoint: the log shows your first commit. Review git status before committing; your Java source, README, ignore rules, and Maven configuration (if used) should be staged. Review any remaining files rather than adding them blindly.

6 · Set up GitHub and push your code

Create an account and an empty practice repository

  1. Visit GitHub’s sign-up page. Create a personal account with a professional username, or use your existing account.
  2. Verify your email. Add your university email under Settings → Emails and verify it through the message GitHub sends. Keep a personal email too for access after graduation.
  3. Enable two-factor authentication under Settings → Password and authentication, and save recovery codes securely.
  4. Select + → New repository. Use your personal account as owner; name the repository wix1002-week1-lab. Choose Private unless your lecturer requests a different visibility.
  5. Leave the README, .gitignore, and licence initialisation options unselected: your project already has a local first commit. Click Create repository and copy its HTTPS URL.

Authenticate using your browser

GitHub does not accept an account password for HTTPS Git pushes. One browser-based setup uses the official GitHub CLI:

  1. Install GitHub CLI using its OS-specific instructions. Reopen your terminal and check gh --version.
  2. Run gh auth login. Choose GitHub.com → HTTPS → Login with a web browser. Say Yes if asked to authenticate Git with your GitHub credentials.
  3. Follow the displayed device-code and browser instructions. Confirm you are signing in to your own account.
  4. Run gh auth setup-git and gh auth status.

If Git Credential Manager is already installed and offers browser sign-in during a push, you can use that instead. See GitHub’s credential guidance. Do not put passwords or access tokens in your code or repository URL.

Connect, push, and check

In the project root, replace YOUR-USERNAME with your username. These commands assume the project has no existing remote named origin.

git remote add origin https://github.com/YOUR-USERNAME/wix1002-week1-lab.git
git remote -v
git push -u origin main
  1. Refresh the repository on GitHub. Confirm your README and Java source appear.
  2. Change the third Java output line to I can track my code with Git. Save and run it.
  3. Record and upload the change:
git diff
git add src
git commit -m "Update the lab greeting"
git push
git log --oneline

Check the latest commit on GitHub. Your repository should show two versions with clear commit messages.

Troubleshooting Git and GitHub
  • Author identity unknown: configure your name and email, then retry.
  • Not a git repository: check the terminal is inside your project root.
  • Remote origin already exists: inspect git remote -v. To correct a wrong URL, use git remote set-url origin followed by the correct HTTPS URL.
  • Repository not found / permission denied: check the URL and the account shown by gh auth status.
  • Push rejected because the remote has commits: a README may have been added on GitHub. Ask your tutor to help reconcile histories; do not force-push to fix this lab.
  • Nothing to commit: save the file and inspect git diff and git status.
Use your personal practice repository, not the course website repository. Follow separate GitHub Classroom or assessment instructions when provided. On shared computers, use gh auth logout and sign out of the browser after finishing.

7 · Apply for the GitHub Student Developer Pack

The Student Developer Pack offers developer tools from GitHub and partner services to verified students. A free GitHub account is enough for the Git exercise above; you can finish the lab while your application is pending.

Check eligibility and prepare evidence

  • Have a personal GitHub account, be at least 13, and be currently enrolled in a degree- or diploma-granting programme.
  • Prepare evidence of current student status: a student ID with a current enrolment date, class schedule, transcript, or enrolment verification letter.
  • Add and verify your academic email. GitHub may require an academic email for your institution; the email alone does not guarantee approval.
  • Use readable evidence showing your identity, institution, and current enrolment. If your ID has no current date, use another accepted document.

Submit your application

  1. Sign in to your personal GitHub account.
  2. Open Settings → Education benefits.
  3. Under GitHub Education, click Start an application, then choose the student option if asked.
  4. Complete the form with your actual institution and enrolment details. Choose your verified academic email if requested.
  5. Provide the requested proof of enrolment using the form’s current upload or verification instructions.
  6. Click Submit application. Check Education benefits and your email for the result. Review time varies; approval is not guaranteed or necessarily immediate.

Redeem benefits after approval

  1. Return to GitHub Education and open the Student Developer Pack.
  2. Select an offer you need. Read its eligibility requirements, duration, usage limits, and renewal terms.
  3. Follow the provider’s redemption steps. Some require a separate provider account; verification does not automatically activate every offer.
  4. Record the offers you activated and their expiry dates. Reverify student status if GitHub requests it later.
If your application is rejected or your school is not recognised

Read the stated reason, correct inaccurate details or replace unclear/outdated evidence, and reapply as directed. If the academic email domain is not recognised, contact GitHub Education support with your institution’s full name, website, and email domain. If your institution does not issue academic email addresses, GitHub’s official guidance explains how to provide documentation of that policy.

Keep verification documents private. Submit student IDs and enrolment evidence through the Education application, not a repository or public issue. Do not include them in lab screenshots. Offers and application screens can change; check the official pages for current terms.
