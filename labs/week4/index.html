LAB 03 · QUESTION 01

Simple calculator

Read two integers and an operator character; print the sum, difference, product, quotient, or remainder.

Enter two integer number: 30 5
Enter the operand: /
30 / 5 = 6

Sample run from the worksheet. Use String.charAt(0) to obtain the operator character.

Model IPO and pseudocode

Input: two int values and one operator character. Process: select the matching operation; guard division and remainder against a zero divisor. Output: the expression and its result.

START
INPUT first, second
INPUT operator as the first character of the next token
SWITCH operator
    '+' : DISPLAY first + second
    '-' : DISPLAY first - second
    '*' : DISPLAY first * second
    '/' : IF second = 0 DISPLAY error ELSE DISPLAY first / second
    '%' : IF second = 0 DISPLAY error ELSE DISPLAY first % second
    otherwise : DISPLAY invalid operator
END
Reveal complete JDK 27 program
import java.util.Scanner;

public class SimpleCalculator {
    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);
        System.out.print("Enter two integer number: ");
        int first = keyboard.nextInt();
        int second = keyboard.nextInt();
        System.out.print("Enter the operand: ");
        char operator = keyboard.next().charAt(0);

        switch (operator) {
            case '+':
                System.out.println(first + " + " + second + " = " + (first + second));
                break;
            case '-':
                System.out.println(first + " - " + second + " = " + (first - second));
                break;
            case '*':
                System.out.println(first + " * " + second + " = " + (first * second));
                break;
            case '/':
                if (second == 0) {
                    System.out.println("Cannot divide by zero");
                } else {
                    System.out.println(first + " / " + second + " = " + (first / second));
                }
                break;
            case '%':
                if (second == 0) {
                    System.out.println("Cannot divide by zero");
                } else {
                    System.out.println(first + " % " + second + " = " + (first % second));
                }
                break;
            default:
                System.out.println("Invalid operator: " + operator);
        }
    }
}

Common mistakes

Comparing a char with a String, for example operator == "+", does not compile; use the char literal '+'. Forgetting break makes the next case run too. Without the zero check, int division or remainder by zero throws ArithmeticException. The worksheet does not say what to do for zero or an unknown operator; the model prints a message for both. int arithmetic can overflow: 2147483647 + 1 prints −2147483648.

LAB 03 · QUESTION 02

Random integer in words

Generate a random integer from 0 to 5 inclusive and display it in words.

2 is two.

Browser random results need not match Java. Generate several times: every value 0–5 should appear eventually, and 6 never should.

Model IPO and pseudocode

Input: none. Process: generate 0–5, then select the matching word. Output: the number and its word.

START
GENERATE number in the inclusive range 0 to 5
SELECT word for number (0 zero, 1 one, ..., 5 five)
DISPLAY number "is" word
END
Reveal complete JDK 27 program
import java.util.Random;

public class NumberInWords {
    public static void main(String[] args) {
        Random generator = new Random();
        int number = generator.nextInt(6); // 0 to 5 inclusive

        String word = switch (number) {
            case 0 -> "zero";
            case 1 -> "one";
            case 2 -> "two";
            case 3 -> "three";
            case 4 -> "four";
            default -> "five";
        };
        System.out.println(number + " is " + word + ".");
    }
}
nextInt(6) returns 0–5 because the bound is exclusive. The switch expression must cover every int value, so default supplies “five”; it can only receive 5 here. A traditional switch statement with six cases and break is an equally valid answer.
LAB 03 · QUESTION 03

Sales commission

Read the sales volume, choose the commission rate from the table, and display the commission to two decimal places.

Sales volumeCommission
Less than or equal to 1005% of total sales
Greater than 100 and less than or equal to 5007.5% of total sales
Greater than 500 and less than or equal to 100010% of total sales
Greater than 100012.5% of total sales
Model IPO and pseudocode

Input: sales volume (double). Process: test the upper limit of each band in ascending order and apply that band’s rate to the total sales. Output: commission to two decimals.

START
INPUT sales
IF sales <= 100 THEN rate = 0.05
ELSE IF sales <= 500 THEN rate = 0.075
ELSE IF sales <= 1000 THEN rate = 0.10
ELSE rate = 0.125
SET commission = sales * rate
DISPLAY commission to two decimal places
END
Reveal complete JDK 27 program
import java.util.Locale;
import java.util.Scanner;

public class SalesCommission {
    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in).useLocale(Locale.US);
        System.out.print("Enter the sales volume: ");
        double sales = keyboard.nextDouble();

        if (sales < 0) {
            System.out.println("Sales volume cannot be negative");
            return;
        }

        double rate;
        if (sales <= 100) {
            rate = 0.05;
        } else if (sales <= 500) {
            rate = 0.075;
        } else if (sales <= 1000) {
            rate = 0.10;
        } else {
            rate = 0.125;
        }
        double commission = sales * rate;
        System.out.printf(Locale.US, "Commission: %.2f%n", commission);
    }
}

Common mistakes

Each else-if is reached only when the previous upper limit failed, so the lower limits (> 100, > 500) need not be repeated. Using < instead of <= puts 100, 500, and 1000 in the wrong band. The table applies one rate to the total sales, not a tiered tax-style calculation. Writing 7.5 instead of 0.075 multiplies by 100. Negative sales are outside the table, so the model rejects them.

Two-player dice game

Each player rolls a die twice; the player with the higher total wins.

Player 1

Player 2

Browser random rolls need not match Java. Totals range from 2 to 12.

Model IPO and pseudocode

Input: none. Process: generate four rolls of 1–6, total each player’s two rolls, compare the totals. Output: every roll, both totals, and the winner or a draw.

START
GENERATE p1First, p1Second, p2First, p2Second in the range 1 to 6
SET player1 = p1First + p1Second
SET player2 = p2First + p2Second
IF player1 > player2 DISPLAY "Player 1 wins!"
ELSE IF player2 > player1 DISPLAY "Player 2 wins!"
ELSE DISPLAY "It's a draw!"
END
Reveal complete JDK 27 program
import java.util.Random;

public class DiceGame {
    public static void main(String[] args) {
        Random dice = new Random();

        int p1First = dice.nextInt(6) + 1;  // 1 to 6
        int p1Second = dice.nextInt(6) + 1;
        int p2First = dice.nextInt(6) + 1;
        int p2Second = dice.nextInt(6) + 1;

        int player1 = p1First + p1Second;
        int player2 = p2First + p2Second;

        System.out.println("Player 1 rolls " + p1First + " and " + p1Second + ": " + player1);
        System.out.println("Player 2 rolls " + p2First + " and " + p2Second + ": " + player2);

        if (player1 > player2) {
            System.out.println("Player 1 wins!");
        } else if (player2 > player1) {
            System.out.println("Player 2 wins!");
        } else {
            System.out.println("It's a draw!");
        }
    }
}
The worksheet does not mention a tie, but equal totals happen often (for example 3 + 4 and 5 + 2). An if-else with only two outcomes would award a tie to one player. Use a three-way else-if chain.
Check the range

nextInt(6) returns 0–5, so nextInt(6) + 1 returns 1–6. nextInt(6) alone could roll 0 and never 6; nextInt(7) could roll 0. Generate each roll separately: reusing one roll for both throws doubles a single value.

LAB 03 · QUESTION 05

Cramer’s rule

Solve ax + by = e and cx + dy = f using x = (ed − bf) / (ad − bc) and y = (af − ec) / (ad − bc).

Model IPO and pseudocode

Input: a, b, c, d, e, f (double). Process: calculate the determinant ad − bc; if it is zero, stop with the message; otherwise apply both formulas. Output: x and y, or the message.

START
INPUT a, b, c, d, e, f
SET determinant = a * d - b * c
IF determinant = 0 THEN
    DISPLAY "The equation has no solution"
ELSE
    SET x = (e * d - b * f) / determinant
    SET y = (a * f - e * c) / determinant
    DISPLAY x and y
END
Reveal complete JDK 27 program
import java.util.Locale;
import java.util.Scanner;

public class CramersRule {
    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in).useLocale(Locale.US);
        System.out.print("Enter a, b, c, d, e, f: ");
        double a = keyboard.nextDouble();
        double b = keyboard.nextDouble();
        double c = keyboard.nextDouble();
        double d = keyboard.nextDouble();
        double e = keyboard.nextDouble();
        double f = keyboard.nextDouble();

        double determinant = a * d - b * c;
        if (determinant == 0) {
            System.out.println("The equation has no solution");
        } else {
            double x = (e * d - b * f) / determinant;
            double y = (a * f - e * c) / determinant;
            System.out.printf(Locale.US, "x = %.2f, y = %.2f%n", x, y);
        }
    }
}
a, b, c, d, e, fExpected
2, 1, 1, −1, 5, 1x = 2.00, y = 1.00
1, 2, 3, 4, 5, 6x = −4.00, y = 4.50
1, 2, 2, 4, 3, 6The equation has no solution
Why check the determinant first?

Dividing a double by zero does not throw an exception in Java: it produces Infinity or NaN. The program must test ad − bc before dividing. Strictly, a zero determinant means no unique solution: the two lines are parallel (no solution) or the same line (infinitely many). The third test case is the same line twice; the worksheet’s message is kept. Check a result by substituting x and y back into both equations.

LAB 03 · QUESTION 06

Point inside or outside a circle

Read a radius and a point (x, y). Decide whether the point lies inside the circle centred at (0, 0).

Model IPO and pseudocode

Input: radius, x, y (double). Process: distance = √(x² + y²); compare it with the radius. Output: inside or outside.

START
INPUT radius, x, y
SET distance = squareRoot(x * x + y * y)
IF distance <= radius THEN DISPLAY "inside"
ELSE DISPLAY "outside"
END
Reveal complete JDK 27 program
import java.util.Locale;
import java.util.Scanner;

public class PointInCircle {
    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in).useLocale(Locale.US);
        System.out.print("Enter the radius of the circle: ");
        double radius = keyboard.nextDouble();
        System.out.print("Enter a point (x y): ");
        double x = keyboard.nextDouble();
        double y = keyboard.nextDouble();

        double distance = Math.sqrt(x * x + y * y);
        if (distance <= radius) {
            System.out.printf(Locale.US, "Point (%.2f, %.2f) is inside the circle%n", x, y);
        } else {
            System.out.printf(Locale.US, "Point (%.2f, %.2f) is outside the circle%n", x, y);
        }
    }
}
Radius, x, yDistanceExpected

Boundary choice and an alternative

The worksheet names only two outcomes. The model counts a point exactly on the circle as inside (<=); state your choice, or add a third “on the circle” branch. Comparing squares, x * x + y * y <= radius * radius, avoids Math.sqrt and gives the same decision for a non-negative radius. x ^ 2 is not a square in Java: ^ is XOR, and it does not compile for double operands.
