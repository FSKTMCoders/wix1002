WEEK 03 / 06

Short-circuit evaluation

The left operand can determine the result before the right is evaluated.

int divisor = 0;
int total = 12;
boolean safe = divisor != 0 && total / divisor > 2;
System.out.println(safe); // false; division is skipped
ExpressionWhen the right side is skipped
A && BA is false
A || BA is true

Put a safety check before the operation it protects. Reversing the operands above attempts division by zero.

String name = null;
boolean present = name != null && !name.isEmpty(); // false

null means no object reference. Calling name.isEmpty() on null throws NullPointerException. With boolean operands, & and | evaluate both sides; use && and || for these guards.

Try it first

Will divisor == 0 || total / divisor > 2 divide when divisor is zero?

Reveal explanation

No. Its left side is true, so OR skips the division and returns true.

WEEK 03 / 07

Precedence and readable conditions

Parentheses make the intended grouping visible.

boolean allowed = age >= 18 && hasCard || isStaff;
// Equivalent grouping:
boolean same = (age >= 18 && hasCard) || isStaff;
// A different rule:
boolean different = age >= 18 && (hasCard || isStaff);

For the operators used here: arithmetic is evaluated before relational comparisons; comparisons before &&; && before ||. NOT applies to its operand.

Try it first

For age = 16, hasCard = false, isStaff = true, evaluate allowed and different.

Reveal explanation

allowed is true because staff status is an alternative route. different is false because everybody must satisfy the age requirement. Write the rule in words before choosing parentheses.

// Valid range test:
boolean valid = 0 <= mark && mark <= 100;
// Invalid Java: 0 <= mark <= 100

WEEK 03 / 09

Braces define the body

Indentation helps readers; braces determine which statements belong together.

int result = 70;
if (result < 50)
    System.out.println("You did not pass");
    System.out.println("Try again"); // Runs regardless of result
if (result < 50) {
    System.out.println("You did not pass");
    System.out.println("Try again");
}

The first version controls only one statement and prints Try again for result = 70. The second version prints neither line.

Use braces even for one statement. Adding another statement later then preserves the intended branch.
Try it first

What does the second version print for result = 49 and result = 50?

Reveal explanation

49 prints both messages. 50 prints neither.

The if-else statement

Choose exactly one of two alternatives.

int time = 20;
if (time < 18) {
    System.out.println("Good day");
} else {
    System.out.println("Good evening");
}

time = 20 prints Good evening. At the boundary time = 18, the condition is false, so Good evening also prints.

Try it first

The source uses if (myScore > yourScore) → “I Win!”, else → “You Win!”. What happens at a tie?

Reveal explanation

The else branch prints You Win even at a tie. If ties are possible, add a separate comparison and a third outcome.

boolean passed = mark >= 50;
if (passed) {

WEEK 03 / 11

Comparing String content

Use equals or equalsIgnoreCase to compare text.

String answer = "yes";
if ("yes".equals(answer)) {
    System.out.println("Confirmed");
}
if ("yes".equalsIgnoreCase(answer)) {
    System.out.println("Confirmed ignoring case");
}
ComparisonMeaning
s1 == s2Do these references identify the same object?
s1.equals(s2)Do these strings have equal content?
s1.equalsIgnoreCase(s2)Is the content equal when case is ignored?
String a = new String("Java");
String b = new String("Java");
System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true

String literals may share an object, which can make a wrong == test appear to work. Test with independently created strings or keyboard input.

The literal-first form "yes".equals(answer) is false when answer is null and avoids calling a method on a null reference. Case-insensitive equality does not remove surrounding spaces.

WEEK 03 / 12

String ordering with compareTo

Use the sign of the result, rather than assuming −1 or +1.

String first = "Aina";
String second = "Bala";
int order = first.compareTo(second);
if (order < 0) {
    System.out.println(first + " comes before " + second);
} else if (order > 0) {
    System.out.println(first + " comes after " + second);
} else {
    System.out.println("Equal content");
}
ResultInterpretation
NegativeReceiver comes before the argument
ZeroEqual content
PositiveReceiver comes after the argument

String.compareTo uses lexicographic comparison based on UTF-16 char values. This is not locale-aware dictionary ordering. compareToIgnoreCase ignores case differences for its comparison.

Try it first

Why can "Z".compareTo("a") be negative?

Reveal explanation

Uppercase Z has char value 90; lowercase a has value 97. The result is −7, not −1. The source description of ordering as ASCII is incomplete for Java strings.

WEEK 03 / 13

Multiway selection with else-if

Evaluate conditions from top to bottom and run the first matching branch.

if (myScore > yourScore) {
    System.out.println("I Win!");
} else if (myScore < yourScore) {
    System.out.println("You Win!");
} else {
    System.out.println("Tie!");
}
if (time < 12) {
    System.out.println("Good morning");
} else if (time < 18) {
    System.out.println("Good day");
} else {
    System.out.println("Good evening");
}

Once a condition is true, the later conditions in the chain are skipped. In the time example, the second branch is reached only after time < 12 is false. Assume time is a valid integer hour 0–23.

WEEK 03 / 15

Separate if statements versus an else-if chain

Separate conditions can all run; a chain chooses one branch.

int mark = 85;
if (mark >= 80) {
    System.out.println("A");
}
if (mark >= 50) {
    System.out.println("Pass");
} // Prints A and Pass
if (mark >= 80) {
    System.out.println("A");
} else if (mark >= 50) {
    System.out.println("Pass");
} // Prints only A

Use separate if statements when each action is independently required. Use a chain when the categories are mutually exclusive.

Try it first

What happens if a grading chain tests mark >= 50 before mark >= 80?

Reveal explanation

85 reaches the first branch. The later A branch is never reached for any mark that is at least 80. Test the higher lower-bound thresholds first.

WEEK 03 / 17

Traditional switch statements

Select a case by an exact value, then use break to leave the switch.

int number = 2;
switch (number) {
    case 1:
        System.out.println("Satu");
        break;
    case 2:
        System.out.println("Dua");
        break;
    case 3:
        System.out.println("Tiga");
        break;
    default:
        System.out.println("Enter 1, 2, or 3");
}

number = 2 prints Dua. default handles an unmatched value. Without a matching label or default, this ordinary int switch statement executes no case body.

Use if/else for ranges and compound rules. Use a basic switch for discrete choices such as menu codes or named commands.

For this lesson use an int or a non-null String selector. These examples work in JDK 25 without preview flags. Extensions involving additional primitive selector types are preview features in JDK 25 and are outside this lesson.

WEEK 03 / 18

Fall-through and missing break

With colon cases, execution can continue into the next case body.

int month = 1;
switch (month) {
    case 1:
        System.out.println("January");
    case 2:
        System.out.println("February");
        break;
    default:
        System.out.println("Other month");
} // Prints January, then February

After entry into case 1, Java does not test whether month equals 2 before continuing into its statements. Fall-through is sometimes intentional; make that intention explicit.

WEEK 03 / 19

Arrow switch rules in JDK 25

Arrow rules execute the matching rule without falling through.

int day = 4;
switch (day) {
    case 1 -> System.out.println("Monday");
    case 2 -> System.out.println("Tuesday");
    case 3 -> System.out.println("Wednesday");
    case 4 -> System.out.println("Thursday");
    case 5 -> System.out.println("Friday");
    case 6, 7 -> System.out.println("Weekend");
    default -> System.out.println("Invalid day");
}
switch (choice) {
    case 1 -> {
        System.out.println("Coffee");
        System.out.println("Preparing your drink");
    }
    case 2 -> System.out.println("Tea");
    default -> System.out.println("Invalid choice");
}

Use a block for multiple statements in one arrow rule. No break is required. Do not mix colon groups and arrow rules in the same switch block.

Arrow switch rules are established language features available in JDK 25, not features introduced specifically in that release.

WEEK 03 / 20

Switch expressions choose a value

An expression supplies a result that can be assigned to a variable.

String drink = switch (choice) {
    case 1 -> "Coffee";
    case 2 -> "Tea";
    default -> "Invalid choice";
};
System.out.println(drink);
double price = switch (choice) {
    case 1 -> 5.0;
    case 2 -> {
        double basePrice = 3.0;
        yield basePrice; // Provides this branch's value
    }
    default -> 0.0;
};

A switch expression must be exhaustive. Here default covers all other int values. In a block rule, yield supplies the expression result; break does not supply a value. The semicolon after the closing brace completes the variable declaration.

For these examples, choices are numeric and non-null. A String selector that is null throws NullPointerException unless null is explicitly handled; default alone does not handle null.

WEEK 03 / 21

The ternary operator selects one value

Use condition ? valueIfTrue : valueIfFalse for a short expression.

String status = mark >= 50 ? "Pass" : "Fail";
System.out.println(status);

int larger = a >= b ? a : b;
double magnitude = x >= 0 ? x : -x;

The condition is evaluated first. Only the chosen alternative is evaluated. Alternatives are expressions that produce values, not arbitrary statement blocks.

int divisor = 0;
int result = divisor != 0 ? 12 / divisor : 0;
// result = 0; division is skipped
Prefer if/else when each branch performs several actions or when nesting ternary expressions makes the rule difficult to read.
Try it first

Predict int x = -7; int y = x >= 0 ? x : -x;.

Reveal explanation

y is 7. For an int version, negating Integer.MIN_VALUE overflows and remains negative; do not assume this formula is safe for every int.

WEEK 03 / 23

Worked program: classify a mark

Translate a decision table into a complete Java console program.

Classroom rules: integer marks 0–100; A ≥ 80, B ≥ 70, C ≥ 60, D ≥ 50, F below 50. These are illustrative thresholds, not official UM grading rules.

import java.util.Scanner;

public class GradeDecision {
    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);
        System.out.print("Enter an integer mark (0-100): ");
        if (!keyboard.hasNextInt()) {
            System.out.println("Invalid input: enter an integer");
            return;
        }
        int mark = keyboard.nextInt();
        String grade;
        if (mark < 0 || mark > 100) {
            grade = "Invalid mark";
        } else if (mark >= 80) {
            grade = "A";
        } else if (mark >= 70) {
            grade = "B";
        } else if (mark >= 60) {
            grade = "C";
        } else if (mark >= 50) {
            grade = "D";
        } else {
            grade = "F";
        }
        System.out.println("Result: " + grade);
    }
}
javac --release 25 GradeDecision.java
java GradeDecision

hasNextInt() checks the token before nextInt() consumes it. The return statement ends main after invalid input. Every path reaching the final println assigns grade.

This program reads one whitespace-delimited token. It does not reject extra trailing tokens. Save it under the exact filename shown and check java --version and javac --version both report 25.

Practice: coffee or tea in two ways

Implement the source question using if-else and switch.

Pair activity · 8 minutes

Read an integer choice: 1 → Coffee, 2 → Tea, otherwise → Invalid choice. Write one solution with if-else and another with switch. Check choices 1, 2, 0, and 3. First predict the outputs on paper.

Reveal complete comparison program
import java.util.Scanner;

public class DrinkOrder {
    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);
        System.out.print("1 = Coffee, 2 = Tea: ");
        if (!keyboard.hasNextInt()) {
            System.out.println("Enter an integer choice");
            return;
        }
        int choice = keyboard.nextInt();
        String byIf;
        if (choice == 1) {
            byIf = "Coffee";
        } else if (choice == 2) {
            byIf = "Tea";
        } else {
            byIf = "Invalid choice";
        }
        String bySwitch = switch (choice) {
            case 1 -> "Coffee";
            case 2 -> "Tea";
            default -> "Invalid choice";
        };
        System.out.println("if-else: " + byIf);
        System.out.println("switch: " + bySwitch);
    }
}

Both implementations must follow the same specification. default is necessary in this int switch expression. Try writing the switch with colon cases and break as a second exercise.

Vibe coding: specify the decision rules

An AI draft needs a precise rule and an independent check.

Vibe coding describes developing by prompting AI in natural language and iterating on its output, often with limited attention to the code. In this course, use any permitted AI assistance to practise reading, explaining, and testing the result.

1 · Specify

State inputs, allowed values, thresholds, output, and JDK version.

2 · Predict

Write expected results for normal and boundary inputs before asking AI.

3 · Inspect and run

Trace conditions and compile the draft. Compare results with your own table.

4 · Revise and explain

Give a failing example, request a correction, rerun tests, and explain the fix.

A program that compiles can still implement the wrong rule. A confident AI explanation does not establish that its boundaries are correct.

WEEK 03 / 28

AI code review: three decision errors

Review this deliberately flawed draft against the stated grading rules.

int mark = 80;
String grade;
if (mark < 0 && mark > 100) {
    grade = "Invalid mark";
} else if (mark >= 50) {
    grade = "D";
} else if (mark > 80) {
    grade = "A";
} else if (mark >= 70) {
    grade = "B";
} else if (mark >= 60) {
    grade = "C";
} else {
    grade = "F";
}
System.out.println(grade);
Review activity · 8 minutes

Find the impossible condition, the branch-order error, and the equality-boundary error. Predict the results for −1, 80, and 101. Compile success alone will not reveal the defects.

Reveal findings and repair order
  1. mark < 0 && mark > 100 can never be true. Use OR for values outside the range.
  2. The first valid branch accepts every mark ≥ 50, so the later A/B/C branches are unreachable at run time. Put thresholds in descending order.
  3. mark > 80 excludes 80. The A rule requires ≥ 80.

Original outputs: −1 → F; 80 → D; 101 → D. Expected: Invalid mark; A; Invalid mark. The complete GradeDecision program earlier shows the corrected implementation.

WEEK 03 / 31

Key takeaways, practice, and references

Choose the branch structure that matches the problem.

Conditions

Comparisons produce booleans. Combine constraints with &&, ||, and !. Keep guards before unsafe operations.

Branch structure

Use a chain for one category, independent if statements for independent actions, and switch for discrete choices.

Text and values

Use equals for String content. Arrow rules avoid fall-through; ternary and switch expressions choose values.

Verification

Check normal, boundary, and invalid inputs. Read and explain every AI-generated condition.

Practice before the tutorial and lab

  2. Write a greeting selector for integer hours 0–23, rejecting invalid hours.

  4. Rewrite DrinkOrder using colon cases and break. Explain one missing-break error.
