WEEK 07 / 03

Part A · What is a method?

A named block of code that performs one specific task.

Modules in Java

Modules in Java are called methods and classes. Methods allow the programmer to modularise a program: write a piece of logic once and reuse it wherever it is needed.

Methods belong to classes

All methods in Java must belong to a class. Methods are similar to the functions of other languages, and they expose an object's behaviour.

Without a method

System.out.println("==========");
System.out.println("  REPORT  ");
System.out.println("==========");
// ... 40 lines later ...
System.out.println("==========");
System.out.println("  REPORT  ");
System.out.println("==========");

The same three lines are copied. A change of title must be made in every copy.

With a method

static void printBanner() {
    System.out.println("==========");
    System.out.println("  REPORT  ");
    System.out.println("==========");
}
// in main:
printBanner();
// ... 40 lines later ...
printBanner();

The logic is written once and called by name. Each call runs the whole body.

Try it first

You have been calling methods since Week 2. Name three, and say what each one belongs to.

Reveal answer

Examples: System.out.println(...) (called on the object System.out), Math.sqrt(x) and Math.random() (static methods of the class Math), keyboard.nextInt() (a Scanner object), and text.length() and text.charAt(i) (a String object). You have also written one method every week: main, which belongs to your class.

WEEK 07 / 04

Why use methods?

Breaking code into separate methods improves readability, reusability, and maintainability.

Code reusability

Write once, use many times without repeating code.

Modularity

Each method handles one specific task, so the program is organised into parts that are easier to manage.

Readability

Smaller, well-named methods make the code easier to read and understand: printBanner() says what happens.

Maintainability

Bugs are easier to fix and code is easier to update when each task lives in one place.

Fix it once

MeasureCopied codeOne method

Methods do not make a program run faster; they make it easier for people to write, test, read, and change. Each method can be tested on its own before it is used by the rest of the program.

WEEK 07 / 05

Anatomy of a method

A header that describes the method, and a body that does the work.

accessSpecifier returnType methodName(parameterType parameterName, …) {
    // method body
}
  • The access specifier for methods is usually public.
  • The return type is the type of value the method returns. It can be a primitive type or an object type. Use void if the method returns nothing.
  • The method name follows the identifier rules; by convention it is a verb in camelCase, such as printLine or calculateTotal.
  • The parameter list declares the inputs, each with a type and a name, separated by commas. It may be empty: ().

Select a part of the header to see what it means.

Header builder

The method's signature is its name plus its parameter types, for example max(int, int). The return type and the parameter names are not part of the signature.

WEEK 07 / 06

Define once, call many times

A call jumps into the method; the end of the method jumps back.

Follow the flow of control

CALL STACK (TOP FRAME FIRST)
CONSOLE OUTPUT
When a method is called, the statements in its body run from the top. When the body ends (or a return runs), control goes back to the statement after the call. main never needs to know how myMethod does its job, only its name.
Static method: call it by name
static void myMethod() {
    System.out.println("I just got executed!");
}

public static void main(String[] args) {
    myMethod();     // outputs "I just got executed!"
}
Instance method: call it on an object
public void printMessage() {
    System.out.println("Hello from an instance method!");
}

public static void main(String[] args) {
    MethodBasics obj = new MethodBasics();  // create an object
    obj.printMessage();                     // call the method on it
}
The course slides show both styles. Most methods in WIX1002 programs are static, like main; Part D explains the difference.
Full program: MethodBasics.java
public class MethodBasics {
    // A static method: called by its name, without creating an object.
    static void myMethod() {
        System.out.println("I just got executed!");
    }

    // An instance method: called on an object of the class.
    public void printMessage() {
        System.out.println("Hello from an instance method!");
    }

    public static void main(String[] args) {
        myMethod();                              // define once ...
        myMethod();                              // ... call as often as needed
        myMethod();

        MethodBasics obj = new MethodBasics();   // create an object of this class
        obj.printMessage();                      // call the method on that object
    }
}



WEEK 07 / 07
Part B · Parameters and arguments
Parameters carry information from the caller into the method.
  • Most methods have a list of parameters. Parameters are the means of communicating information between methods via method calls. A method can have no parameters, one, or several.
  • A method is invoked by a method call. The call gives the method's name and provides the correct arguments according to the parameters' sequence and type.
  • When the call completes, the method either returns a result to the caller or simply returns control to it.

WEEK 07 / 08
Returning a value
return sends a value back and ends the method at once.
  • The body of a method that returns a value must contain at least one return statement, and every path through the body must reach one.
  • A return statement always ends the method invocation. Statements after it on the same path never run.
  • To return a value: return variableName; (or any expression of the return type).
  • To end a void method early, use return; with no expression.
Value-returning
static int max(int x, int y) {
    if (x > y)
        return x;
    else
        return y;
}
The call max(7, 12) is an expression with the value 12.
void with early exit
static void printLine(char symbol, int n) {
    if (n <= 0) {
        return;        // no value
    }
    for (int i = 0; i < n; i++)
        System.out.print(symbol);
    System.out.println();
}
The call printLine('*', 5); is a statement; it has no value.
Returned values are expressions
int bigger = max(a, b);
System.out.println(max(a, b) * 2);
int best = max(max(3, 9), 5);  // 9
Store it, print it, use it in a calculation, or pass it to another call.
Which return runs?
Full program: MaxDemo.java
public class MaxDemo {
    // Precondition: none; any two int values are allowed.
    // Postcondition: returns the larger of x and y.
    public static int max(int x, int y) {
        if (x > y)
            return x;
        else
            return y;
    }

    // Precondition: none.
    // Postcondition: prints n copies of symbol on one line; prints nothing if n <= 0.
    public static void printLine(char symbol, int n) {
        if (n <= 0) {
            return;                              // void method: end early, no value
        }
        for (int i = 0; i < n; i++) {
            System.out.print(symbol);
        }
        System.out.println();
    }

    public static void main(String[] args) {
        int a = 7, b = 12;
        int bigger = max(a, b);                  // the call is replaced by its returned value
        System.out.println("max(" + a + ", " + b + ") = " + bigger);
        printLine('*', bigger);
        System.out.println(max(max(3, 9), 5));   // a returned value can be an argument
        printLine('-', 0);                       // prints nothing
    }
}
The compiler checks every path. A statement directly after return in the same block is an error (unreachable statement), and a value-returning method whose last path has no return is an error (missing return statement).

Method calls step by step
Each call pushes a frame on the call stack; each return pops it.
CALL STACK (TOP FRAME FIRST)
CONSOLE OUTPUT
A frame holds one call's parameters and local variables. The method that is running is always the top frame. sumOfSquares is paused at the middle of its expression while square runs, and continues with the returned value.
Full program: CallTrace.java
public class CallTrace {
    static int square(int n) {
        int result = n * n;
        return result;
    }

    static int sumOfSquares(int a, int b) {
        int total = square(a) + square(b);
        return total;
    }

    public static void main(String[] args) {
        int x = 3;
        int y = 4;
        int answer = sumOfSquares(x, y);
        System.out.println("answer = " + answer);
    }
}
Try it first
With x = 3 and y = 4, how many frames are on the stack at the moment result is assigned 16? Name them from top to bottom.
Reveal answer
Three: square (n = 4, result = 16), sumOfSquares (a = 3, b = 4, waiting for the second square), and main (x = 3, y = 4, waiting for answer).



WEEK 07 / 10
Local variables and scope
Same name, different method, different variable.
  • A variable declared inside a method is a local variable. Parameters are local variables too.
  • Each method can use the same variable name; these are still different variables, stored in different memory locations (different frames).
  • A local variable exists only while its method is running, and can be used only inside the block where it is declared.
static int addOne(int count) {
    count = count + 1;
    int total = count * 2;
    return total;
}

public static void main(String[] args) {
    int count = 5;
    int total = addOne(count);
    System.out.println(count + " " + total);
}

WEEK 07 / 11
Part C · Call-by-value
The method receives a copy of each argument's value.
In Java, all method invocations are call-by-value. When you invoke a method, a copy of the value of each actual parameter (argument) is passed to the method. Any change to the copy inside the method has no effect on the actual parameter.
static void changeInt(int x) {
    x = 10;            // changes the copy only
}

public static void main(String[] args) {
    int number = 5;
    changeInt(number);
    System.out.println(number);   // 5
}
Try it first
A classmate writes this method to swap two variables. What does main print?
static void swap(int a, int b) {
    int hold = a;
    a = b;
    b = hold;
}
// in main:
int x = 1, y = 2;
swap(x, y);
System.out.println(x + " " + y);
Reveal answer
1 2. The method swaps its own copies a and b; x and y in main are untouched. A method cannot swap two primitive variables of its caller. (It can swap two elements of an array the caller passes in: that is Part C's next idea.)



WEEK 07 / 12
Primitive and reference types
A primitive variable holds a value; a reference variable holds an address.
Why does this matter in methods?
static void changeAge(Dog d) {
    d.age = 10;   // THIS WORKS: changes the real object
}
The address is copied, so the method's d refers to the same object as the caller's variable.
static void changeInt(int x) {
    x = 10;       // does NOT affect the original
}
The value is copied; the method changes only its own copy.
Objects and arrays are reference types. Java does not manipulate objects and arrays directly; it manipulates references to them. So when an object or array is a parameter, changes to the object's instance variables or to the array's elements affect the actual parameter. A variable of class type stores the reference of where the object is located in memory, so a method can change the instance variables of an argument of a class type. The Java primitive types are not reference types.
null: an empty reference
int x = null;   // ❌ compile error: primitives can't be null
Dog d = null;   // ✅ valid: d refers to no object
The constant null can be assigned to a variable of class type to show that it has no real object. Using it as if it had one, for example d.age = 1;, throws a NullPointerException at run time. You met this in Week 6 with rows of a ragged array that were never created.
SummaryPrimitiveReference
StoresThe value directlyA memory address
Can be null?❌ No✅ Yes
Can a method change the original?❌ No✅ Yes: the object's fields or the array's elements

Two precise points. (1) The reference itself is still passed by value: if a method assigns a new object or array to its parameter (d = new Dog();), the caller's variable still refers to the old one. (2) String is a reference type, but a String object cannot be changed (it is immutable): s = s + "!" builds a new String, so a String argument behaves like a primitive in practice. Try both in the lab on the next page.
Full program: DogDemo.java
class Dog {
    int age;
}

public class DogDemo {
    static void changeAge(Dog d) {
        d.age = 10;                        // THIS WORKS: changes the real object
    }

    static void changeInt(int x) {
        x = 10;                            // does NOT affect the original
    }

    public static void main(String[] args) {
        Dog rex = new Dog();               // rex holds a reference to a Dog object
        rex.age = 3;
        int years = 3;

        changeAge(rex);
        changeInt(years);
        System.out.println("rex.age = " + rex.age);
        System.out.println("years = " + years);

        Dog nobody = null;                 // valid: a reference to no object
        // int x = null;                   // compile error: a primitive cannot be null
        System.out.println("nobody == null is " + (nobody == null));
        // nobody.age = 1;                 // would throw NullPointerException
    }
}

public class CallByValueDemo {
    static void changeInt(int x) {
        x = 10;                            // changes the copy only
    }

    static void changeElement(int[] a) {
        a[0] = 99;                         // follows the copied reference to the caller's array
    }

    static void replaceArray(int[] a) {
        a = new int[] {7, 7, 7};           // the copy now refers to a different array
        a[0] = 1;                          // changes the new array, not the caller's
    }

    static void changeText(String s) {
        s = s + "!";                       // builds a new String; the caller's variable is unchanged
    }

    public static void main(String[] args) {
        int number = 5;
        changeInt(number);
        System.out.println("after changeInt:     number = " + number);

        int[] values = {1, 2, 3};
        changeElement(values);
        System.out.println("after changeElement: values[0] = " + values[0]);

        replaceArray(values);
        System.out.println("after replaceArray:  values[0] = " + values[0]);

        String word = "Java";
        changeText(word);
        System.out.println("after changeText:    word = " + word);
    }
}

WEEK 07 / 15
Part D · Static methods
A static method does not need a calling object.
  • A static method is a method that does not require a calling object. Its definition is inside the class definition.
  • To define a static method: public static returnType methodName(parameterType parameter, …)
  • To invoke a static method in the same class, just use the method name: methodName(…).
  • To invoke a static method from a different class, use the class name: ClassName.methodName(…).
class Test {
    static void hello() {
        System.out.println("Hello");
    }
}

public class StaticCalls {
    static int square(int n) {
        return n * n;
    }

    public static void main(String[] args) {
        Test.hello();              // other class
        System.out.println(square(6));   // same class
    }
}
You already use library static methods
The Java library is full of static methods, called the same way: ClassName.methodName(arguments). Each call has a value of the method's return type.
Full program: StaticCalls.java
class Test {
    static void hello() {
        System.out.println("Hello");
    }
}

public class StaticCalls {
    static int square(int n) {
        return n * n;
    }

    public static void main(String[] args) {
        Test.hello();                              // another class: ClassName.methodName()
        System.out.println(square(6));             // same class: methodName()
        System.out.println(StaticCalls.square(7)); // the class name is optional here
        System.out.println(Math.max(4, 9));        // library static methods work the same way
        System.out.println(Math.sqrt(81));
    }
}
A file may contain several classes but only one public class, whose name matches the file name: StaticCalls.java contains the public class StaticCalls and the helper class Test.

WEEK 07 / 18
Part E · Preconditions and postconditions
A method's comment is a contract between the caller and the method.
Precondition (requirement)
States what is assumed to be true when the method is called: what the caller must guarantee before the method starts. It defines the input requirements, so the method does not receive garbage data.
Example: the input age must be an integer greater than 0.
Postcondition (guarantee)
Describes the effect of the method call and the value it returns: what the method promises will be true after it finishes, provided the preconditions were met. It ensures the method did its job and broke nothing.
Example: after withdraw(50), balance == oldBalance - 50.
/*
 * Withdraws an amount from a balance.
 * Precondition:  amount > 0 and amount <= balance.
 * Postcondition: returns the new balance,
 *                equal to balance - amount (never negative).
 */
static double withdraw(double balance, double amount) {
    return balance - amount;
}
Contract checker
If the caller breaks the precondition, the method's promise no longer applies: here withdraw(200, 500) returns −300, which the postcondition says should never happen. The caller can check first (as in the program below), or the method can check its own input and report a problem. Either way, the comment tells everyone who is responsible.
Full program: WithdrawContract.java
public class WithdrawContract {
    /*
     * Withdraws an amount from a balance.
     * Precondition:  amount > 0 and amount <= balance.
     * Postcondition: returns the new balance, equal to balance - amount (never negative).
     */
    static double withdraw(double balance, double amount) {
        return balance - amount;
    }

    public static void main(String[] args) {
        double balance = 200.00;
        double[] requests = {50.00, 500.00, -20.00};

        for (int i = 0; i < requests.length; i++) {
            double amount = requests[i];
            if (amount > 0 && amount <= balance) {      // the caller guarantees the precondition
                double oldBalance = balance;
                balance = withdraw(balance, amount);
                System.out.printf("Withdraw %.2f: %.2f -> %.2f (postcondition %s)%n", amount,
                        oldBalance, balance, balance == oldBalance - amount ? "holds" : "broken");
            } else {
                System.out.printf("Withdraw %.2f refused: amount must be > 0 and <= %.2f%n",
                        amount, balance);
            }
        }
    }
}
Try it first
Write a precondition and a postcondition for static double average(int[] marks).
Reveal answer
Precondition: marks is not null and has at least one element (otherwise the division by marks.length fails). Postcondition: returns the arithmetic mean of the elements as a double; marks is unchanged. The second part matters because an array is passed by reference: callers need to know the method will not reorder or modify their data.

Full program: ScoreReport.java
public class ScoreReport {
    // Precondition: scores has at least one element.
    // Postcondition: returns the mean of the scores; scores is unchanged.
    static double average(int[] scores) {
        int sum = 0;
        for (int i = 0; i < scores.length; i++) {
            sum += scores[i];
        }
        return (double) sum / scores.length;
    }

    // Precondition: scores has at least one element.
    // Postcondition: returns the largest score; scores is unchanged.
    static int highest(int[] scores) {
        int best = scores[0];
        for (int i = 1; i < scores.length; i++) {
            if (scores[i] > best) {
                best = scores[i];
            }
        }
        return best;
    }

    // Postcondition: returns how many scores are at least limit.
    static int countAtLeast(int[] scores, int limit) {
        int count = 0;
        for (int i = 0; i < scores.length; i++) {
            if (scores[i] >= limit) {
                count++;
            }
        }
        return count;
    }

    // Postcondition: returns "Pass" for 50 or more, otherwise "Fail".
    static String result(int score) {
        return score >= 50 ? "Pass" : "Fail";
    }

    // Postcondition: prints the name, score, result, and one '#' per 10 marks.
    static void printRow(String name, int score) {
        System.out.printf("%-6s%4d  %-5s", name, score, result(score));
        for (int i = 0; i < score / 10; i++) {
            System.out.print('#');
        }
        System.out.println();
    }

    public static void main(String[] args) {
        String[] names = {"Aina", "Ben", "Chen", "Devi", "Eric"};
        int[] scores = {78, 45, 91, 62, 38};

        for (int i = 0; i < scores.length; i++) {
            printRow(names[i], scores[i]);
        }
        System.out.printf("Average: %.2f%n", average(scores));
        System.out.println("Highest: " + highest(scores));
        System.out.println("Passed:  " + countAtLeast(scores, 50) + " of " + scores.length);
    }
}

Review: three bugs an AI assistant might produce
1 · Integer average
static double average(int[] m) {
    int sum = 0;
    for (int i = 0; i < m.length; i++)
        sum += m[i];
    return sum / m.length;
}
{70, 85, 60} gives 71.0, not 71.67.
2 · Early “not found”
static int indexOf(int[] m, int key) {
    for (int i = 0; i < m.length; i++) {
        if (m[i] == key) return i;
        else return -1;
    }
    return -1;
}
Finds 70 but not 85.
3 · Swapping copies
static void swap(int a, int b) {
    int hold = a;
    a = b;
    b = hold;
}
// called as swap(m[0], m[2]);
The array never changes.
Reveal the corrections
// 1: divide as double
return (double) sum / m.length;

// 2: decide "not found" only after the loop
for (int i = 0; i < m.length; i++)
    if (m[i] == key) return i;
return -1;

// 3: pass the array and the two indexes
static void swap(int[] m, int i, int j) {
    int hold = m[i];
    m[i] = m[j];
    m[j] = hold;
}

1. Which of these headers are valid?

Reveal answer
Only g and h. f needs a type for each parameter: (int a, int b). k has no return type; write void or a type.
Try it first
2. What is printed?
static int triple(int n) { return n * 3; }
// in main:
System.out.println(triple(triple(2)) + triple(1));
Reveal answer
21: triple(2) = 6, triple(6) = 18, triple(1) = 3, and 18 + 3 = 21.
Try it first
3. What is printed?
static void fill(int[] a, int v) {
    for (int i = 0; i < a.length; i++) a[i] = v;
    v = 0;
}
// in main:
int[] data = new int[3];
int seven = 7;
fill(data, seven);
System.out.println(data[2] + " " + seven);
Reveal answer
7 7. The array is changed through the copied reference; v = 0 changes only the method's copy of 7.
Try it first
4. main calls a(), a calls b(), and b calls c(). While c runs, how many frames are on the stack, and which method runs after c returns?
Reveal answer
Four frames (c on top, then b, a, main). After c returns, b continues from the statement after its call to c.

For example public static int countChar(String text, char target). Precondition: text is not null. Postcondition: returns a count from 0 to text.length().

WEEK 07 / 24
Key takeaways, practice, and references
Small named methods, clear contracts, tested one at a time.
Defining and calling
A method is a named block of code inside a class. Header: access specifier, static, return type, name, parameter list. Arguments match parameters by number, order, and type.
Returning
Every path of a value-returning method ends in return value;. return ends the call at once; void methods may use return;.
Call-by-value
Every argument is copied. Primitives cannot be changed by a method; the objects and arrays a copied reference leads to can. Assigning to a parameter never changes the caller's variable.
Static methods and contracts
Static methods need no object: name() in the same class, ClassName.name() elsewhere. main is static and receives String[] args. Preconditions bind the caller; postconditions bind the method.
