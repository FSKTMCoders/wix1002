WEEK 04 / 04

Revision: three ways to select

The same decision written as an else-if chain, a ternary expression, and a switch.

if-else-if

Ranges and compound rules. The first true condition wins.

int a = 15;
if (a == 5) {
    System.out.println("a is equal to 5");
} else if (a == 10) {
    System.out.println("a is equal to 10");
} else {
    System.out.println("a is not equal to 5 or 10");
}

Ternary operator

Chooses one of two values inside an expression.

int a = 10;
System.out.println(a == 5 ? "a is equal to 5"
                          : "a is not equal to 5");

switch

Matches exact values. break prevents fall-through.

int a = 15;
switch (a) {
    case 5:
        System.out.println("a is equal to 5");
        break;
    case 10:
        System.out.println("a is equal to 10");
        break;
    default:
        System.out.println("a is not equal to 5 or 10");
}

With a = 15 the first and third programs print “a is not equal to 5 or 10”. With a = 10 the ternary program prints “a is not equal to 5”.

The source wraps these snippets in class GFG with import java.io.*;. The import is unnecessary because System.out belongs to java.lang.

Question

Read an integer score (0–100). 90 or above → A; 80–89 → B; 70–79 → C; 60–69 → D; below 60 → F. If the score is below 0 or above 100, print “Invalid score”.

public class GradeChecker {
    public static void main(String[] args) {
        int score = 85;
        if (score < 0 || score > 100) {
            System.out.println("Invalid score");
        } else if (score >= 90) {
            System.out.println("Grade: A");
        } else if (score >= 80) {
            System.out.println("Grade: B");
        } else if (score >= 70) {
            System.out.println("Grade: C");
        } else if (score >= 60) {
            System.out.println("Grade: D");
        } else {
            System.out.println("Grade: F");
        }
    }
}

switch on score / 10

public class GradeCheckerSwitch {
    public static void main(String[] args) {
        int score = 85; // change this value

        if (score < 0 || score > 100) {
            System.out.println("Invalid score");
        } else {
            int gradeGroup = score / 10; // 0-10 after integer division
            switch (gradeGroup) {
                case 10:
                case 9:
                    System.out.println("Grade: A");
                    break;
                case 8:
                    System.out.println("Grade: B");
                    break;
                case 7:
                    System.out.println("Grade: C");
                    break;
                case 6:
                    System.out.println("Grade: D");
                    break;
                default:
                    System.out.println("Grade: F");
            }
        }
    }
}

Integer division groups the scores: 85 / 10 is 8, and 100 / 10 is 10. Cases 10 and 9 share one body by intentional fall-through. Validation must come first; otherwise 105 / 10 = 10 would become A.

WEEK 04 / 07

In-class question: ATM withdrawal

Combine a limit calculation with an ordered chain of rules.

Given

int balance = 1200; int withdrawAmount = 750; int day = 6; boolean isPremiumUser = false; (1 = Monday … 7 = Sunday)

  1. If withdrawAmount > balance → “Insufficient balance”.
  2. If withdrawAmount is not a multiple of 50 → “Invalid amount (must be multiple of 50)”.
  3. Limit: Saturday or Sunday (6, 7) → 500; weekday → 1000. A premium user’s limit increases by 500.
  4. If withdrawAmount exceeds the limit → “Exceeds daily limit”.
  5. Otherwise deduct the amount and print “Transaction successful” and “Remaining balance: X”.
Reveal the solution
public class ATMSystem {
    public static void main(String[] args) {
        int balance = 1200;
        int withdrawAmount = 750;
        int day = 6; // 1 = Monday ... 7 = Sunday
        boolean isPremiumUser = false;
        int limit;

        // Determine the base limit
        if (day == 6 || day == 7) {
            limit = 500;
        } else if (day >= 1 && day <= 5) {
            limit = 1000;
        } else {
            System.out.println("Invalid day");
            return;
        }

        // Add the premium bonus
        if (isPremiumUser) {
            limit += 500;
        }

        // Check the rules in order
        if (withdrawAmount > balance) {
            System.out.println("Insufficient balance");
        } else if (withdrawAmount % 50 != 0) {
            System.out.println("Invalid amount (must be multiple of 50)");
        } else if (withdrawAmount > limit) {
            System.out.println("Exceeds daily limit");
        } else {
            balance -= withdrawAmount;
            System.out.println("Transaction successful");
            System.out.println("Remaining balance: " + balance);
        }
    }
}

Explore the rules

The given values print “Exceeds daily limit”: 750 is affordable and a multiple of 50, but the weekend limit is 500. Making the user premium raises the limit to 1000, leaving a balance of 450.

The return statement ends main for an invalid day, so the later rules never run. The model uses whole-ringgit int values, as in the source.

WEEK 04 / 08

Introduction to repetition

A repetition flow repeats an action while some condition remains true.

In Java, the while, do-while, and for statements provide repetition. Each pass through the loop body is called an iteration.

Count-controlled loop

Executes the statements a fixed number of times. The program knows the count before the loop begins, such as “print Hello 5 times”.

Sentinel-controlled loop

Executes the statements repeatedly until a special value, the sentinel, is encountered, such as “read marks until −1 is entered”.

WEEK 04 / 09

Count-controlled versus sentinel-controlled

Ask: does the loop stop after a fixed number, or when a particular value arrives?

Count-controlled

for (int i = 1; i <= 5; i++) {
    System.out.println("Hello");
}

Prints Hello exactly 5 times.

Sentinel-controlled

Scanner keyboard = new Scanner(System.in);
System.out.print("Enter number (-1 to stop): ");
int num = keyboard.nextInt();
while (num != -1) {
    System.out.println("You entered " + num);
    System.out.print("Enter number (-1 to stop): ");
    num = keyboard.nextInt();
}

Stops whenever the user enters −1; the count is unknown in advance.

TypeWhen does it stop?Example
Count-controlled loopAfter a fixed number of iterations5 times

The source sketch sets num = 0; inside the sentinel loop. Because 0 never equals −1, that sketch never stops. A sentinel loop must obtain a new value in every iteration; this version reads it with Scanner (import java.util.Scanner).

The while statement

Test the condition first; repeat the body while it is true.

while (condition)
    statement;

// Use braces for more than one statement
while (condition) {
    statement1;
    statement2;
    statement3;
}
Something inside the body must eventually make the condition false. Without braces, only the first statement belongs to the loop.
WEEK 04 / 11

while: sum the numbers 1 to 10

Step through each iteration and watch two variables change.

int number = 1, sum = 0;
while (number <= 10) {
    sum += number;
    number++;
}
System.out.println("Sum = " + sum); // Sum = 55

Iteration stepper

The condition is tested 11 times: true for number = 1…10 and false for number = 11. The body runs 10 times. After the loop, number is 11 and sum is 55.

WEEK 04 / 13

Question: palindrome number

Use a while loop to reverse the digits, then compare.

Question

Start with int number = 1221;. Use a while loop to reverse the number, then print the reversed number and whether it is “Palindrome” or “Not Palindrome”. A palindrome reads the same forward and backward: 1221 → 1221 is a palindrome; 1234 → 4321 is not.

Reveal the solution
public class PalindromeCheck {
    public static void main(String[] args) {
        int number = 1221;
        int original = number;
        int reversed = 0;

        while (number != 0) {
            int digit = number % 10;          // last digit
            reversed = reversed * 10 + digit; // append it
            number = number / 10;             // remove it
        }

        System.out.println("Reversed = " + reversed);
        if (original == reversed) {
            System.out.println("Palindrome");
        } else {
            System.out.println("Not Palindrome");
        }
    }
}

Main idea

Is the number the same when reversed? If yes → Palindrome. If no → Not Palindrome.

Why save original?

The loop changes number until it becomes 0, so the starting value must be kept for the final comparison.

WEEK 04 / 14

Trace the digit reversal

Three operations per iteration: extract, build, remove.

  1. int digit = number % 10; extracts the last digit: 1221 % 10 = 1.

  2. reversed = reversed * 10 + digit; shifts the reversed digits left and appends the new one: 0 → 1 → 12 → 122 → 1221.

  3. number = number / 10; removes the last digit by integer division: 1221 → 122 → 12 → 1 → 0.

  4. The loop stops when number is 0. Compare original with reversed.

Stepnumber (before)digitreversednumber (after)

Try 1221, 1234, 7, 0, 1000, and 12321. For 1000 the reversal is 1 (leading zeros disappear), so it is not a palindrome. The limit avoids int overflow: reversing some 10-digit int values exceeds 2,147,483,647.

WEEK 04 / 23

break ends the loop

A break statement ends the nearest enclosing loop (or switch).

int sum = 0;
for (int count = 1; count <= 10; count++) {
    if (count == 5)
        break; // leave the loop when count is equal to 5
    sum += count;
}
// sum = 1 + 2 + 3 + 4 = 10

When count reaches 5, the loop ends immediately. The remaining statements in the body, the update, and every later iteration are skipped. Execution continues after the loop.

WEEK 04 / 24

continue skips one iteration

A continue statement ends the current iteration and proceeds with the next.

int sum = 0;
for (int count = 1; count <= 10; count++) {
    if (count == 5)
        continue; // skip the remaining statements when count = 5
    sum += count;
}
// sum = 55 - 5 = 50

Compare break and continue

In a for loop, continue moves to the update (count++). In a while loop, continue jumps straight to the condition, so an update placed after it is skipped and can cause an infinite loop.

WEEK 04 / 25

Labels with break and continue

A label names a statement so that break or continue can target an outer loop.

int counter = 0;
stop: { // label statement
    for (int row = 1; row <= 10; row++) {
        for (int column = 1; column <= 5; column++) {
            if (row == 5)
                break stop; // break the stop label statement
            counter++;
        }
    }
} // end of the labelled block
// counter = 20

Which cells are counted?

A plain break leaves only the inner column loop, so row 5 is skipped and rows 6–10 still count (45). break stop leaves the whole labelled statement (20). A label can also be placed directly on the outer loop: outer: for (...), then continue outer; starts its next iteration.

The source example omits the closing brace of the labelled block; it is added here. Labelled jumps are useful for nested searches but can make code harder to follow. Prefer a clear condition when one is available.

WEEK 04 / 26

Common loop errors

These programs usually compile; they repeat the wrong number of times.

Off-by-one error

The loop iterates once too often or once too few times. Check the condition and the initial value of the counter.

Infinite counting loop

The counter goes the wrong way or does not change at all. Make sure the counter changes correctly in the loop.

Infinite sentinel loop

New data are not input at the end of the loop body, so the sentinel can never arrive.

Bug simulator

The simulator stops after 12 iterations. A real Java program with an infinite loop keeps running until you stop it (in a terminal, press Ctrl+C; in NetBeans, use the Stop button).
WEEK 04 / 27
Off-by-one and infinite counting loops
Compare each wrong version with its correction.
1 · Off-by-one
// Wrong: prints 1 2 3 4
for (int i = 1; i < 5; i++) {
    System.out.println(i);
}

// Correct: prints 1 2 3 4 5
for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}
The loop stops too early when the intention is 1 to 5.
2 · Counter never changes
// Wrong: i stays 1, prints 1 forever
int i = 1;
while (i <= 5) {
    System.out.println(i);
}

// Correct
int i = 1;
while (i <= 5) {
    System.out.println(i);
    i++; // fix: update counter
}
i <= 5 is always true when i never changes.
Counter going the wrong way
int i = 5;
while (i <= 10) {
    System.out.println(i);
    i--; // wrong direction: 5, 4, 3, ... never reaches 11
}
Replace i-- with i++ to print 5 to 10.
Strictly, the int eventually overflows from −2,147,483,648 to 2,147,483,647 and the wrong-direction loop ends after about 2.1 billion iterations. That is still a bug: treat it as an infinite loop.
WEEK 04 / 28
Infinite sentinel loop
The value that is tested must be replaced in every iteration.
Wrong
int number = 1;
while (number != -1) {
    System.out.println(number);
    // missing update (no new input)
}
number never changes, so the condition is always true.
Correct (simulated input)
int number = 5;
while (number != -1) {
    System.out.println(number);
    number--; // simulate new input
}
Prints 5, 4, 3, 2, 1, 0 and stops when number becomes −1.
In a real program, the “update” of a sentinel loop is the next read: number = keyboard.nextInt(); at the end of the body, as in the next worked program.
WEEK 04 / 29
Worked program: average marks until −1
A complete sentinel-controlled loop with a priming read.
import java.util.Scanner;

public class SentinelSum {
    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);
        final int SENTINEL = -1;
        int sum = 0;
        int count = 0;

        System.out.print("Enter a mark 0-100 (-1 to stop): ");
        int mark = keyboard.nextInt();         // priming read

        while (mark != SENTINEL) {
            if (mark < 0 || mark > 100) {
                System.out.println("Ignored: marks must be 0-100");
            } else {
                sum += mark;
                count++;
            }
            System.out.print("Enter a mark 0-100 (-1 to stop): ");
            mark = keyboard.nextInt();         // new input before the next test
        }

        if (count == 0) {
            System.out.println("No marks entered");
        } else {
            double average = (double) sum / count;
            System.out.printf("Count: %d, Sum: %d, Average: %.2f%n", count, sum, average);
        }
    }
}
javac --release 25 SentinelSum.java
java SentinelSum
The first read happens before the loop (the priming read), so the condition always has a value to test. The second read is the last statement of the body. If −1 is entered first, the body never runs and the count check avoids dividing by zero.
This model expects integer tokens. A non-integer token such as abc throws InputMismatchException; Week 3’s hasNextInt() check can be added as an extension. Save the file as SentinelSum.java and check that java --version and javac --version both report 25.
WEEK 04 / 30
Vibe coding: specify the loop rules
An AI draft can only follow the stopping rule you actually state.
Vibe coding describes developing by prompting AI in natural language and iterating on its output. In this course, use any permitted AI assistance to practise reading, tracing, and testing the result, not to skip understanding it.
1 · Specify
State the start, the stopping condition or sentinel, the update, valid values, the output, and JDK 25.
2 · Predict
Write expected results for zero, one, and several iterations before asking AI.
3 · Trace and run
Record loop variables per iteration. Compile and compare with your own table.
4 · Revise and explain
Give a failing case, request a correction, rerun every test, and explain why the loop now stops.
A loop that compiles can still run once too often, never run, or never stop. Ask yourself for every loop: which statement makes the condition false?

AI code review: three loop errors
The specification: for n ≥ 1, print the sum of the odd numbers from 1 to n inclusive; otherwise print “Invalid n”.
int n = 7;
int sum = 0;
for (int i = 1; i < n; i += 2) {
    sum = i;
}
System.out.println("Sum of odd numbers: " + sum);
Review activity · 8 minutes
Find the boundary error, the accumulation error, and the missing validation. Predict the output for n = 7, n = 8, and n = 0. The expected results are 16, 16, and Invalid n.
Reveal findings and repair
  1. i < n excludes n itself. When n is odd (7), the last odd number is skipped. Use i <= n.
  2. sum = i overwrites the total in every iteration. Use sum += i.
  3. Nothing handles n < 1; the program prints 0 for n = 0. Check n before the loop.
if (n < 1) {
    System.out.println("Invalid n");
} else {
    int sum = 0;
    for (int i = 1; i <= n; i += 2) {
        sum += i;
    }
    System.out.println("Sum of odd numbers: " + sum);
}
Original outputs: n = 7 → 5; n = 8 → 7; n = 0 → 0.

Repetition self-check and exit ticket
Predict each output, then reveal the reasoning.
Try it first
1. What is the output? for (int i = 0; i <= 5; i += 2) { System.out.print(i + " "); }
Reveal answer
0 2 4. The next value, 6, fails i <= 5.
Try it first
2. Find and fix the error: int i = 1; while (i < 5) { System.out.println(i); }
Reveal answer
i is never updated, so the loop is infinite and prints 1 forever. Add i++; as the last statement of the body; the loop then prints 1 to 4.
Try it first
3. What is the output? int i = 10; do { System.out.println(i); i++; } while (i < 5);
Reveal answer
10. A do-while runs at least once, even if the condition is false.
Try it first
4. What is the output?
int x = 5;
if (x > 2)
    if (x > 10)
        System.out.println("A");
    else
        System.out.println("B");
Reveal answer
B. The else belongs to the nearest unmatched if, if (x > 10), which is false.
Try it first
5. What is the output?
for (int i = 1; i < 4; i++);
{
    System.out.println("Hello");
}
Reveal answer
Hello, printed once. The semicolon is the loop’s empty body; the loop repeats nothing three times. The block afterwards is ordinary code that runs once.

WEEK 04 / 35
Key takeaways, practice, and references
Choose the loop whose stopping rule is easiest to see.
Loop types
Count-controlled loops stop after a fixed number; sentinel-controlled loops stop when a special value arrives.
Three statements
for and while test first and may run zero times. do-while tests last and runs at least once.
Changing the flow
break ends the nearest loop; continue skips to the next iteration; labels target an outer statement.
Verification
