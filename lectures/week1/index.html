WEEK 01 / 03

Computers need precise instructions

A computer accepts data, follows instructions, and produces results. It can also store data and results for later use.

Hardware

Physical parts such as the processor, memory, keyboard, and screen.

Software

Programs: instructions that tell hardware what to do.

Data

Values that a program works with, such as a name, a price, or a distance.

Human robot · 3 minutes

Tell a partner how to make a cup of tea. Your partner follows only the steps you explicitly give.

“Add some water” leaves questions: how much, into what container, and at what temperature?

Why does the order matter?

If you pour the tea before placing the cup, the same actions produce a different result. Programs also depend on the order of instructions.

A program is a set of instructions expressed in a programming language. Small programs may contain only a few instructions.
WEEK 01 / 04

Programming languages

Different languages describe instructions at different levels of detail.

LevelWhat it looks likeHow it reaches the processor
Machine languageBinary-encoded instructions: 0s and 1sThe processor executes instructions for its instruction set.
Assembly languageMOV AL, 88hAn assembler translates symbolic instructions into machine code. This example depends on a particular instruction set.
High-level languagetotal = price * quantity;A compiler or runtime translates or executes the program. Java first compiles to bytecode.

High-level languages help us express calculations and decisions without describing every hardware operation. Java is a high-level language.

Algorithm vs language: the algorithm is your plan. Java is one language you can use to express that plan.
Is a high-level language just ordinary English?

No. It uses precisely defined syntax and meaning. A computer cannot execute a vague English description as Java code.

WEEK 01 / 06

How a Java program runs

The original five-stage model remains useful: edit, compile, load, verify, and execute.

  1. Edit

    Write source code and save FirstProgram.java.

  2. Compile

    javac FirstProgram.java checks language rules and produces FirstProgram.class containing bytecode.

  3. Load

    The JVM class loader brings the required classes into memory.

  4. Verify

    The JVM checks structural and type-safety properties of bytecode. This does not prove your algorithm is correct.

  5. Execute

    java FirstProgram launches the class. The JVM may interpret bytecode and compile frequently executed code into machine code.

Source file

FirstProgram.java

Compiled file

FirstProgram.class

Java bytecode can run on different platforms with compatible JVMs. Your program can still depend on platform-specific files or libraries.

Why do we omit .class in java FirstProgram?

In this command, FirstProgram is the class name. Run it from the directory containing the compiled class, for this simple example.

Optional: other launch methods

Modern JDKs also support source-file launch, such as java FirstProgram.java. A packaged application may use java -jar app.jar. These notes use the explicit compile-and-run steps to make the process visible.

WEEK 01 / 07

Problem solving starts before code

An algorithm is a finite, clearly specified sequence of steps for solving a task.

Start with a small problem: convert a distance from metres to centimetres. One metre equals 100 centimetres.

Understand

What are the units? Are decimal distances allowed? What should happen for a negative distance?

Solve manually

For 2.5 metres, calculate 2.5 × 100 = 250 centimetres.

Design

Read metres, check the allowed range, multiply by 100, and display centimetres.

Implement

Express the steps in Java and compile the program.

Test and revise

Compare actual results with expected results. Fix the cause of each mismatch.

Iteration is normal. A failed test may reveal a coding mistake, a flawed algorithm, or an unclear requirement. Return to the relevant step.
Think before typing

Write an expected answer for 0 metres and 0.01 metres. Which requirement tells you whether −2 metres is valid?

WEEK 01 / 09

Decomposition and clear requirements

Decomposition means dividing a larger task into smaller tasks that you can reason about.

Example: a campus café bill

Calculate a bill for one item type. Inputs are item price, quantity, and a hypothetical tax rate. This exercise does not specify an actual Malaysian tax rule.

  1. Read and validate the price, quantity, and tax rate.
  2. Calculate subtotal: price × quantity.
  3. Calculate tax: subtotal × taxRate.
  4. Calculate final total: subtotal + tax.
  5. Display a clear bill.
Requirement questionDecision for this example
Can quantity be 0?Yes: the bill is 0. Negative quantity is invalid.
How is the tax rate entered?As a fraction: 0.06 means 6%.
What output precision?Display the final total to two decimal places.
Manual check

Price = RM5.00, quantity = 2, hypothetical tax rate = 0.06. Calculate the expected total before seeing code.

Reveal the calculation

Subtotal = RM10.00. Tax = RM0.60. Total = RM10.60. A rate of 6 would represent 600%, so input conventions matter.

WEEK 01 / 10

Pseudocode: a plan you can read

Pseudocode describes an algorithm without requiring the exact syntax of a programming language.

There is no single universal pseudocode syntax. Consistent names, clear steps, and indentation matter more than one particular set of keywords. Numbering is optional.

Distance conversion

START
READ metres
IF metres < 0 THEN
    DISPLAY "Invalid distance"
ELSE
    centimetres ← metres × 100
    DISPLAY centimetres
END IF
STOP

Useful habits

  • Write one clear action per line.
  • Use descriptive names such as metres.
  • Indent the actions inside an IF or a loop.
  • Make both outcomes of a decision clear.
  • Specify how a loop ends.

← means “assign this value”. Java uses = for assignment.

Try it: trace the pseudocode with 2.5 and then −2. Which lines execute in each case?
WEEK 01 / 11

Three basic control structures

Sequence, selection, and repetition describe how a program chooses its next action.

Sequence

Perform actions in order.

READ price
READ taxRate
tax ← price × taxRate
finalPrice ← price + tax
DISPLAY finalPrice

Selection

Choose a path using a condition.

IF students > 40 THEN
    DISPLAY "Extra classes needed"
ELSE
    DISPLAY "One class is enough"
END IF

Repetition

Repeat while a condition is true.

count ← 0
WHILE count < 10
    count ← count + 1
    DISPLAY count
END WHILE

These examples preserve the ideas in your original lecture: final-price calculation, class capacity, and a counter loop.

What happens when students = 40?

40 > 40 is false. Display “One class is enough”. If the requirement includes 40 in the extra-class category, the condition must change.

Why does the loop terminate?

The count increases on each iteration. After displaying 10, the next check of count < 10 is false. If we remove the increment, the loop never makes progress.

WEEK 01 / 13

Repetition: trace one step at a time

A trace records how values change. It helps you understand a loop without running a program.

count ← 0
WHILE count < 10
    count ← count + 1
    DISPLAY count
END WHILE
Initialise: count = 0. No output yet.
Count before checkConditionCount after incrementOutput
Boundary check: this algorithm displays 1 through 10. It does not display 0. The location of the increment matters.
Extension: the digit-sum example in the original lecture

For a non-negative integer, initialise sum ← 0. Repeatedly take the last digit with remainder by 10, add it to the sum, and remove the last digit using integer division by 10. Stop when the remaining number is 0.

READ number
sum ← 0
WHILE number != 0
    digit ← number MOD 10
    sum ← sum + digit
    number ← number DIV 10
END WHILE
DISPLAY sum

For 123: digits 3, 2, and 1 give a sum of 6. For input 0, the loop does not run and the initial sum of 0 is the answer. Initialising the sum is essential. We will study remainder and integer division later.

WEEK 01 / 15

The plan becomes Java

The distance converter connects the same problem across IPO, pseudocode, a flowchart, and source code.

import java.util.Scanner;

public class DistanceConverter {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        System.out.print("Distance in metres: ");
        double metres = input.nextDouble();

        if (metres < 0) {
            System.out.println("Invalid distance");
        } else {
            double centimetres = metres * 100;
            System.out.println("Distance in cm: " + centimetres);
        }
    }
}

Input

Scanner reads keyboard input. nextDouble() reads a number that can include a decimal part.

Process

metres * 100 performs the conversion. The if selects the negative-value path.

Output

println displays the label and calculated value. Here + joins text with a number.

Save as DistanceConverter.java, compile with javac DistanceConverter.java, then run java DistanceConverter.

Scope of this introductory code: it checks negative numeric values. Entering text such as abc causes an input error. Full input validation is a later improvement.
Predict · run · explain

Try 2.5 and −2. Explain why only one branch runs each time. Change the output message to include your name.

WEEK 01 / 16

Errors and debugging

Debugging means finding the cause of a mistake and checking that the correction works.

ErrorExampleWhat happensUseful response
Syntax / compile-timeSystem.out.println("Hello") without its semicolonCompilation fails. Some compile-time errors concern types or names rather than syntax.Read the first error message. Check the line and the line above it.
Runtimeint result = 10 / 0;The statement throws an arithmetic exception when executed.Reproduce the input and check for a zero divisor.
Logiccentimetres = metres / 100;The program runs but gives the wrong conversion.Compare with a manually calculated expected output.

Syntax describes the permitted structure of code. Semantics describes its meaning and behaviour. Code can be syntactically valid and still implement the wrong calculation.

  1. Reproduce the error with a small input.
  2. Write down the expected and actual results.
  3. Locate the step where they differ.
  4. Fix the cause and repeat the test.
  5. Recheck other cases that the change might affect.
Spot the bug

A converter outputs 0.025 cm for 2.5 metres. Which line would you inspect first, and what answer should you expect?

Reveal the diagnosis

Inspect the formula. It probably divides by 100. The expected answer is 250 cm, so the conversion should multiply by 100.

Choose tests from the requirements. One successful example is not enough.

abcInvalid input formatThe introductory Java example throws an input exception. A more robust version should display a helpful message.

A test case includes input, expected behaviour, and the actual result. Calculate expected answers independently of the program or AI tool.

Selection boundary

The class-capacity condition is students > 40. Test 39, 40, and 41. Why are these more informative than testing only 10 and 100?

Reveal the boundary reasoning

39 and 40 follow the “one class” path. 41 follows the “extra classes” path. These tests help distinguish > from >=.

Verification limit: a compiler checks language rules. Testing checks selected behaviours. Neither automatically proves every possible input is handled correctly.
WEEK 01 / 18

What is vibe coding?

Vibe coding is a loosely defined approach in which you describe what you want in natural language, let AI generate code, and refine the result through further prompts.

The term became popular after Andrej Karpathy introduced it in February 2025. In its original sense, it emphasised following the visible result while paying little attention to the generated code.

Example conversation

You: “Make a Java distance converter.”

AI: proposes code.

You: “Add a check for negative values.”

AI: revises it.

Why people use it

It can help explore an idea quickly, generate a draft, or explain unfamiliar code.

Why beginners need care

A working-looking output can hide incorrect rules, unsupported features, or code you cannot explain. Fluency and confidence are not evidence of correctness.

ApproachYour role
Manual programmingYou design and write the code, then test it.
AI-assisted programmingAI helps you draft or explain code. You read it, understand it, and verify its behaviour.
Vibe coding in the original senseYou focus on prompts and visible results, often with limited inspection of the code. This can leave important mistakes unnoticed.
Learning aim: explore what AI can do while continuing to develop your own problem-solving and Java skills.

Further reading: IBM: What is vibe coding?

WEEK 01 / 19

A guided AI coding workflow

The algorithm, expected answers, and responsibility for the result remain yours.

  1. Plan first

    State the problem, identify IPO, write a manual example, and draft pseudocode.

  2. Describe the task

    Specify Java, a console program, permitted input, output, and any course constraints.

  3. Read the proposed code

    Locate input, calculation, decision, and output. Ask about any unfamiliar line.

  4. Compile and test

    Use your actual course JDK. Compare with your independently calculated answers.

  5. Refine and explain

    Report the exact failed case. Review the revision, retest, and explain the final algorithm in your own words.

Vague request

Make a converter.

A clear learning prompt

I am a first-year Java student.
Help me create a console program named DistanceConverter.
Read a numeric distance in metres using Scanner.
For negative values, print "Invalid distance".
Otherwise multiply by 100 and display centimetres.
Use an explicit public class and the conventional main method.
Use simple variables and if/else. No external libraries.
Explain the IPO and pseudocode before showing Java code.
Give test cases for 2.5, 0, 0.01, and -2.
Also explain what happens if the input is abc.

This is a model prompt. AI responses vary. Specify the course JDK if known, and follow the instructor’s rules for each assessed task.

WEEK 01 / 20

AI code review: catch the hidden mistake

Even a short, plausible AI-generated program deserves a manual check.

An AI response proposes this line for the distance converter:

double centimetres = metres / 100;
Challenge · 4 minutes
  1. Predict its result for 2.5.
  2. Compare with your manual calculation.
  3. Write a follow-up prompt that reports the exact mismatch.
  4. Explain the correction without asking AI.
Reveal a useful follow-up

“For input 2.5 metres, the program outputs 0.025, but the expected answer is 250 centimetres because 1 metre equals 100 centimetres. Check the formula, explain the mistake, and show the corrected line.”

double centimetres = metres * 100;

Learning with AI

  • Ask for a hint before requesting the entire answer.
  • Ask it to explain a line and then verify the explanation.
  • Practise a similar problem without AI.
  • Keep an accurate record of AI help when your assessment requires disclosure.
  • Follow the stated assessment policy. Permission depends on the task.
  • Keep passwords and personal or confidential data out of prompts.
Before accepting code: can you identify its inputs, trace its logic, predict its output, and explain why the tests are sufficient for this exercise?
WEEK 01 / 21

Class activity: design a circle calculator

Work with a partner. Use the same planning skills with a different formula.

Task · 8–10 minutes

Read a numeric radius in centimetres. Reject a negative radius. For a valid radius, display the area in cm² and circumference in cm.

Use area = π × r × r and circumference = 2 × π × r.

  1. Create an IPO table.
  2. Calculate expected answers for r = 0 and r = 2.
  3. Write pseudocode and sketch a flowchart with both decision branches.
  4. Explain what should happen for r = −1 and for text input.
  5. Optional, if permitted: ask AI for simple Java using your plan, then inspect it.
Reveal a model solution after trying
START
READ radius
IF radius < 0 THEN
    DISPLAY "Invalid radius"
ELSE
    area ← π × radius × radius
    circumference ← 2 × π × radius
    DISPLAY area, circumference
END IF
STOP

For r = 0, both results are 0. For r = 2, area = 4π ≈ 12.5664 cm² and circumference = 4π ≈ 12.5664 cm. Use Math.PI in Java. Notice that this particular radius gives the same numerical results with different units.

Extra check: add r = 1: area ≈ 3.1416 cm² and circumference ≈ 6.2832 cm. This helps reveal a mistaken use of one formula for both outputs.

Pair roles: one person explains the algorithm while the other checks the steps and test cases. Then swap roles.

WEEK 01 / 23

Key takeaways and next steps

Programming begins with understanding the task and ends with checking the result.

The plan

Define inputs, outputs, assumptions, and a manual example before writing code.

The representation

Pseudocode and flowcharts express the same algorithm in different forms.

The implementation

Java turns the algorithm into executable instructions. Compilation success does not establish correctness.

The evidence

Trace values and test normal, boundary, and invalid cases.

The AI role

AI can help generate and explain code. You still need to understand and verify it.
